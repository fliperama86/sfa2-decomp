# Sony library part

The files in this folder reconstruct the part of the executable that is the
PlayStation SDK library, not game code. They are not original work of this
project.

## Where they come from

- Project: sotn-decomp, <https://github.com/xeeynamo/sotn-decomp>.
- Commit: `62d03266cc927aabefea3b0605cabc254b48831b`, folder
  `src/main/psxsdk`.
- License: MIT, by the `SPDX-License-Identifier: MIT` line that each of those
  files carries there. The line is kept here, and [`LICENSE`](LICENSE) in
  this folder has the license text with the reference's copyright line.

## What is here

- 99 C files. 54 have the name they have in the reference; 14 of those were
  adapted to the SDK version of this game, 40 are unchanged. 45 files named
  `*_pN.c` are parts of reference files for the functions that compile to
  the exact bytes of this game: 33 cut out by this project's importer, and
  twelve made by hand in the same form (`libapi/counter_p2.c` to
  `libapi/counter_p4.c` and `libgpu/sys_p8.c` to `libgpu/sys_p16.c`,
  below).
- 5 internal headers from the same folder of the reference, 3 of them adapted.
- 42 assembly files for BIOS and system call stubs, generated by this
  project's importer from the reference's one-line stub files.
- 2 assembly files written by hand, `libapi/counter_p5.s` (`StopRCnt`) and
  `libcard/card.s` (`_card_clear`): explicit assembly exceptions, below.

A few functions that the reference does not have were written by this
project. They are in the same files, except two that have a file of their
own: `libsnd/sepopen.c` (`func_80166144`, inferred `SsSepOpen`) and
`libsnd/dataentry.c` (`_SsContDataEntry`; the reference declares a function
of this name and has no definition of it), both written
by this project from the listing of the original, with no text of the
reference and no license line. Neither is one of the files counted
above. Both include the game's headers (`../../game.h` and the two beside
it) and declare what they need of the library itself, so they need none
of the headers of `include/`.

One function that the reference has in a file with others stands in a
file of its own here: `libsnd/vm_alloc.c` (`SpuVmAlloc`), adapted by hand
from the function of that name in the reference's `libsnd/vmanager.c` to
this game's voice record, with the reference's license line. It is not
one of the files counted above either; like `sepopen.c` it includes
the game's headers and declares its own view of the library's records,
and needs none of the headers of `include/`.

One function has a second source: `libsnd/sepinit.c` (`func_80165d84`,
inferred `_SsInitSoundSep`). It was written by this project from the listing
of the original, with `_SsInitSoundSeq` of `seqinit.c` as an aid; the form
that builds the original's bytes was reached after the same function had
been read in the PSY-Q decompilation that the PsyZ project carries,
<https://github.com/Xeeynamo/psyz>, file `decomp/src/libsnd/sepinit.c`, as of
commit `4e4b3e8dc7ae740c085fd190d635f54142d2d552` (the file's last change
there is commit `d0a56bb028f834d10a495c1352279727c7cf7040`). That folder's
license is MIT (`decomp/LICENSE` there). The file here carries the MIT
license line, and [`LICENSE`](LICENSE) has that project's copyright lines.
It is not one of the files counted above; like `sepopen.c` it includes
the game's headers and declares its own view of the library's records, and
needs none of the headers of `include/`.

One function stands between the two parts of the reference's `libspu/spu.c`
in a file of its own: `libspu/spu_init.c` (`_spu_init`, the reset of the
sound chip). It was written by this project from the listing of the
original: the reference's `_spu_init` is of another version of the library,
with another order of stores, and was read for the names of the chip's
registers. Its idle loop is the reference's (`waste_time`, as in
`spu_p1.c`), so the file carries the reference's license line. It is not
one of the files counted above; it includes the game's headers and
declares its own view of the chip's registers, and needs none of the
headers of `include/`. It builds to the original's bytes with the one patch
to the assembler wrapper that `ps1/docs/matching-build.md` describes
(`maspsx_patches`).

`libapi/counter_p2.c` (`ResetRCnt`) is the second part of the reference's
`libapi/counter.c`, made by hand in the form of the importer's parts. Its
declarations are the reference's, the same as in `counter_p1.c`. It
differs from the reference's text in one place, a labelled stand-in: the
store goes through a cast that takes `volatile` off the pointer to the
counter registers. With the reference's plain store the function has 14
instructions where the original has 13 (4 differing instruction slots).
What the original source had there is not known. The unit also names an
assembler version of its own in `build.toml` (`aspsx_version`, described
in `ps1/docs/matching-build.md`): the function's `li` of the constant 1 is
an `addiu` in the original, where the rest of the library has an `ori` for
such a constant. `GetRCnt` builds to the same bytes with either version.

`libapi/counter_p3.c` (`SetRCnt`) and `libapi/counter_p4.c` (`StartRCnt`)
are two more parts of the same file, made by hand in the same form. Their
text is the reference's at the pinned commit, unchanged. They build to
the original's bytes with another compiler than the rest of this
repository: GCC 2.5.7, which their units name in `build.toml` (`cc1`,
described in `ps1/docs/matching-build.md`, which also says where that
binary comes from), with the assembler version of `counter_p2`. With the
project's GCC 2.6.3 `SetRCnt` comes out 4 bytes longer and `StartRCnt`
has one instruction at another place. This is inferred from the bytes:
the build shows that these two functions come out of that compiler, not
which compiler built the library. `GetRCnt` and `ResetRCnt` build to
the same bytes with either compiler and keep the default one.

`libapi/counter_p5.s` (`StopRCnt`, the fifth function of that file) and
`libcard/card.s` (`_card_clear`, the one function of the reference's
`libcard/card.c`) are written by hand in assembly. They are explicit
exceptions, by the owner's decision of 2026-10-11, for two functions of
the library whose C is known (the reference's, at the pinned commit; each
file's comment quotes it) and whose bytes no compiler and assembler step
of this build gives. For `StopRCnt`, GCC 2.5.7 writes the original's
instructions, with its two loads of variables as one line each; the
original has those two lines as five instructions in an order, and with a
temporary register, that this build's assembler step does not produce.
For `_card_clear`, the original keeps the parameter in its argument slot
across a call where every compiler tried keeps it in a saved register;
with the parameter's address taken GCC 2.5.7 comes to four instruction
words off (the return address at another offset of the frame, and the
stack's restore before the return instead of in its delay slot). Seven
compiler versions were tried on both (2.5.7, 2.6.0, 2.6.3, 2.7.0, 2.7.1,
2.7.2 and 2.8.1). What tools made these two objects is
not known; the assembly says what the bytes are, and the comments say
what is inferred.

`libgpu/sys_p8.c` (`get_mode`, `get_cs`, `get_ce`, `get_ofs`) and
`libgpu/sys_p9.c` (`get_dx`) are two more parts of the reference's
`libgpu/sys.c`, made by hand in the form of the importer's parts, with the
declarations that the file's other parts have. The importer had left these
five functions out: it keeps a function only when the reference's text
builds to this game's bytes. Their text here
follows the same functions in the PSY-Q decompilation that the PsyZ
project carries, <https://github.com/Xeeynamo/psyz>, file
`decomp/src/libgpu/sys.c`, as of commit
`4e4b3e8dc7ae740c085fd190d635f54142d2d552` (the file's last change there
is commit `ad36515fabe317c4e525a3ea6ed48db312df6499`); that folder's
license is MIT, and [`LICENSE`](LICENSE) has that project's copyright
lines. What differs from that text is labelled in the files: each
function reads a field of the library's state through a cast to
`volatile` (a labelled stand-in), and `get_cs` and `get_ce` read their
limit once into a local where the reference's `CLAMP` macro names it
twice. What the original source had is not known.

`libgpu/sys_p10.c` (`SetDrawEnv`), `libgpu/sys_p11.c` (`_getctl`),
`libgpu/sys_p12.c` (`_exeque`) and `libgpu/sys_p13.c` (`get_alarm`) are
four more parts of the same file, made by hand in the same form.

Their text is not the pinned commit's text with a few changes. It has
three layers, and only the first is the reference's:

1. The reference's `libgpu/sys.c` at the commit named at the top, MIT.
   The license line and the notice in [`LICENSE`](LICENSE) are kept for
   it.
2. This project's adapted copy of that file. The game links another
   version of the library than the reference reconstructs, so in
   earlier work this project changed function bodies in a working copy
   of the file to what this game's code does, from the original's
   instructions, in the reference's names and style. That copy is a
   private working file; the parts in this folder are cut from it, the
   importer's parts too. Where a body here differs from the pinned
   commit's, the difference is this project's, not the reference's.
3. This batch's changes on top of the adapted copy.

For the four functions, layer 2 against the pinned commit:

- `_getctl` returns the table's entry alone. The pinned text also puts
  the index into the result's high byte.
- `get_alarm` has a limit of 0xF0000 for its count where the pinned text
  has 0x780000, ends its first message with a comma where the pinned
  text ends the line, and has a second `printf`, of the last call's
  three words, that the pinned text does not have.
- `_exeque` is another body. The pinned text walks the queue with labels
  and jumps, tests each entry's function for null, and reaches the
  callback through `CheckCallback`. The adapted body returns 1 while a
  transfer runs, works the queue off in a `do` loop, keeps each call's
  three words, and calls the callback when the queue is empty and the
  pending flag is set.
- `SetDrawEnv` takes the upper limits of the area from the library's
  state (`gs.w - 1`, `gs.h - 1`). The pinned text has constants there.

Layer 3, this batch, each with a comment in its file: `_getctl` nothing;
`get_alarm` one read through a cast to `volatile` (a labelled
stand-in); `_exeque` the same cast at six reads and stores (one
labelled stand-in); `SetDrawEnv` the same cast at two reads (one
labelled stand-in), the lower limit 1 where the adapted copy had 0, and
each upper limit read once into a local. What the original source had
is not known.

`libgpu/sys_p14.c` (`_addque2`), `libgpu/sys_p15.c` (`_clr`, `_dws`,
`_drs`) and `libgpu/sys_p16.c` (`PutDispEnv`) are the last parts of the
same file, made by hand in the same form, with the same three layers.

Layer 2, this project's adapted copy against the pinned commit:

- `_addque2` is another body. The pinned text takes the interrupt mask
  first, runs the call at once when the queue is off or empty, and
  fills a queue entry through a pointer. The adapted body waits for a
  free entry first, sets the pending flag, runs the call at once when
  the queue is off or when it is empty with no transfer and no
  callback, keeping the call's three words, and otherwise fills the
  entry by index.
- `_clr`, `_dws` and `_drs` take the upper limits of the rectangle from
  the library's state (`gs.w - 1`, `gs.h - 1`). The pinned text has
  constants there.
- `PutDispEnv` reads the debug level, the type, the reverse flag and
  the saved display environment as fields of the library's state `gs`.
  The pinned text has a variable of its own for each.

Layer 3, the changes that made them exact, each with a comment in its
file:

- `_addque2`: two stores and a read through a cast to `volatile` (one
  labelled stand-in at three places).
- `_clr`, `_dws`, `_drs`: the rectangle is limited in place where the
  adapted copy limited a copy of it, the lower limit is 1 where the
  adapted copy had 0, each upper limit is read once into a local, and
  it is read through the same cast (one labelled stand-in at two
  places in each function).
- `PutDispEnv`: the type is tested against 1 and 2 where the adapted
  copy tested it against 0; the other form masks the line with 0x3FF
  where the adapted copy had 0x1FF; the first line adds 0x13 when the
  environment's `pad0` is not 0, where the adapted copy had 0x10
  alone; two reads go through the same cast (one labelled stand-in at
  two places).

For `_clr`, `_dws`, `_drs` and `PutDispEnv` the workers who found these
forms read the same functions in the PSY-Q decompilation that the PsyZ
project carries (the file, commit and license named above for
`sys_p8.c`): the limiting in place and the two values of the first line
follow that text's structure. `_addque2` was written at the top level
with nothing else read. What the original source had is not known.

## What is not here

`include/` is not in the repository. The library files need 38 headers of
the reference: 25 from its `include/` folder and 13 from `include/psxsdk/`.
Eight of them carry an AGPL-3.0-or-later tag and the others carry none in a
repository whose license is AGPL-3.0. This repository does not publish them.

To build, copy those headers unchanged from the commit above:

```sh
mkdir -p ps1/src/sdk/include/psxsdk
cp <sotn-decomp>/include/*.h ps1/src/sdk/include/
cp <sotn-decomp>/include/psxsdk/*.h ps1/src/sdk/include/psxsdk/
```
