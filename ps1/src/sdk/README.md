# Sony library part

The files in this folder reconstruct the part of the executable that is the
PlayStation SDK library, not game code. They are not original work of this
project.

## Where they come from

- Project: sotn-decomp, <https://github.com/xeeynamo/sotn-decomp>.
- Commit: `62d03266cc927aabefea3b0605cabc254b48831b`, folder
  `src/main/psxsdk`.
- License: MIT, by the `SPDX-License-Identifier: MIT` line that each of those
  files carries there. The line is kept here, and [`LICENSE`](LICENSE) in
  this folder has the license text with the reference's copyright line.

## What is here

- 87 C files. 54 have the name they have in the reference; 14 of those were
  adapted to the SDK version of this game, 40 are unchanged. 33 files named
  `*_pN.c` are parts of reference files, cut out by this project's importer
  for the functions that compile to the exact bytes of this game.
- 5 internal headers from the same folder of the reference, 3 of them adapted.
- 42 assembly files for BIOS and system call stubs, generated by this
  project's importer from the reference's one-line stub files.

A few functions that the reference does not have were written by this
project. They are in the same files, except one that has a file of its
own: `libsnd/sepopen.c` (`func_80166144`, inferred `SsSepOpen`), written
by this project from the listing of the original, with no text of the
reference and no license line. It is not one of the 87 files counted
above. It includes the game's headers (`../../game.h` and the two beside
it) and declares what it needs of the library itself, so it needs none
of the headers of `include/`.

One function that the reference has in a file with others stands in a
file of its own here: `libsnd/vm_alloc.c` (`SpuVmAlloc`), adapted by hand
from the function of that name in the reference's `libsnd/vmanager.c` to
this game's voice record, with the reference's license line. It is not
one of the 87 files counted above either; like `sepopen.c` it includes
the game's headers and declares its own view of the library's records,
and needs none of the headers of `include/`.

One function stands between the two parts of the reference's `libspu/spu.c`
in a file of its own: `libspu/spu_init.c` (`_spu_init`, the reset of the
sound chip). It was written by this project from the listing of the
original: the reference's `_spu_init` is of another version of the library,
with another order of stores, and was read for the names of the chip's
registers. Its idle loop is the reference's (`waste_time`, as in
`spu_p1.c`), so the file carries the reference's license line. It is not
one of the 87 files counted above; it includes the game's headers and
declares its own view of the chip's registers, and needs none of the
headers of `include/`. It builds to the original's bytes with the one patch
to the assembler wrapper that `ps1/docs/matching-build.md` describes
(`maspsx_patches`).

## What is not here

`include/` is not in the repository. The library files need 38 headers of
the reference: 25 from its `include/` folder and 13 from `include/psxsdk/`.
Eight of them carry an AGPL-3.0-or-later tag and the others carry none in a
repository whose license is AGPL-3.0. This repository does not publish them.

To build, copy those headers unchanged from the commit above:

```sh
mkdir -p ps1/src/sdk/include/psxsdk
cp <sotn-decomp>/include/*.h ps1/src/sdk/include/
cp <sotn-decomp>/include/psxsdk/*.h ps1/src/sdk/include/psxsdk/
```
